设置

这是第三方客户端。本扩展不内置任何 API key，也不代表任何模型厂商。 你在下面配置的服务只会收到你主动发送的内容（提问 + 你勾选附带的正文）。

界面是自建阅读器的一部分，不会去调用 deepseek.com 的网页版聊天， 只按 OpenAI 兼容格式调用你指定的 /chat/completions 接口。

模型服务

仅保存在本机 chrome.storage.local，明文、不同步、不上传。 只有上面这个 Base URL 会收到它。
本地小模型（3B–7B）多数不支持 OpenAI 风格 function calling，关掉更稳； 关掉后模型只能依据消息里附带的「当前页文本」回答。
原样合并进请求 JSON，用于传各家特有参数。例：Ollama 的 Qwen3 / R1 想关掉思考过程用 {"think": false}；限制上下文用 {"options":{"num_ctx":8192}}。 留空则不加。
注意：这个地址是 http:// 且不是本机，API Key 会以明文在网络上传输。 远程服务建议改用 SSH 隧道（ssh -L 11434:127.0.0.1:11434 user@host）， 这样本地回环通信，key 不出本机。

本地文件

本地 PDF/EPUB 用「拖入文件」打开时不需要任何文件权限。
只有想用快捷键 Ctrl+Shift+E 或「打开当前标签页」时才需要： edge://extensions → 本扩展 → 详细信息 → 打开「允许访问文件 URL」。

Ollama / 远程模型

1. 远程机器上启动 Ollama（只监听回环，最安全）：
OLLAMA_HOST=127.0.0.1:11434 ollama serve

2. 本机建 SSH 隧道（保持窗口开着）：
ssh -N -L 11434:127.0.0.1:11434 user@your-server

3. 若直接连报 HTTP 403：这是 Ollama 的来源校验（它默认不放行 chrome-extension://），不是 key 问题。不改服务端的办法：在项目目录执行 npm run relay，然后把服务切到「Ollama（经本地中继）」，Base URL 用 http://127.0.0.1:11500/v1。

4. 有权限的话也可以直接给服务端加 OLLAMA_ORIGINS=chrome-extension://你的扩展ID 再重启，然后仍用 11434 端口。
